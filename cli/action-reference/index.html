Command Line (CLI)

CLI action reference

Every bridge action: what it does, inputs, examples, results, and approvals.

The CLI has simple commands such as show and search, plus access to the running app’s actions. An action is a complete request, such as reading a document or preparing an image. The editing verbs are individual changes sent inside apply or propose_flow_patch; see node changes, reference and stack changes, and Flow details and automations. This page covers the current desktop bridge action surface. Availability depends on the running build, permission level and configured services. Read the actual list with flowjoe-cli actions. get_app_state, query_history and read_history expose current app facts and retained history. Saved history is separate from this command’s recent-change and undo history. Read access includes observational actions, including automation status and app help; it does not grant Flow edits. The editing catalog can still be inspected with Read access, even though applying its verbs requires Propose access. The CLI does not expose MCP resource listing/reading as a command; open_reference supplies app help.

​
Catalog snapshot and permissions

On 2026-10-19, real CLI discovery against a fully provisioned desktop (history, repository, scheduler and help services present) returned 27 actions with Propose access and 20 with Read access. Both profiles included 19 observational read tools; Read’s extra action was upload_attachment, which prepares connection-local input rather than reading existing content. Propose also exposes editing, staging, generation, file import, navigation, player control and undo. A desktop without one of those services lists fewer actions. These action totals are separate from the 62 editing verb names returned by describe_patch_protocol: 61 distinct changes, because setNodeReadOnly is an older name for setNodeFrozen. That catalog includes editRepoFileText. Read can inspect the editing catalog but cannot apply its changes. The current catalog returns 63 names (62 distinct changes) and includes the three virtual-slot verbs: makeVirtualSlotReal, removeVirtualMaster and addVirtualSlot. In get_flow_snapshot, a virtual slot carries virtualSlot: true and its master’s place (virtualOf, masterNodeId, masterSlotIndex) instead of content, or virtualMaster: "hidden_from_joe" when the master can’t be seen; a master carries virtualCount and virtualPlaces. Read actions aimed at a virtual slot read its master and say so in readFrom. A second measurement later on 2026-10-19, after Joe’s workflow hand-offs and picture search landed, returned the same totals, and a direct MCP connection was offered exactly the same actions as the CLI at both access levels. Observational tools in both profiles were get_flow_snapshot, describe_patch_protocol, read_media_blob, get_app_state, query_history, read_history, get_node_neighbors, search_flow, get_island_content, read_item_content, read_media_content, list_joe_memories, list_scheduled_tasks, open_reference, list_recent_changes, get_approval_outcome and read_chat_attachment, read_repository and read_repo_file. Uploads, staging, generation, navigation, player actions and mutations are not counted as observational reads. These are dated measurements, not permanent limits: discover your running app’s catalog before scripting. Native Joe, external MCP and guests can have different services and authority; an owner endpoint does not establish guest or shared-Flow support. Transcription was added after the dated catalog measurements above. Discover the running catalog for current totals.

Transcribe a recording — transcribe_audio

Transcribe an audio recording already in the Flow using saved Transcribe settings. The complete result is kept in Recent transcripts. Propose access is required. Local setup never falls back to paid service. This action is available in Joe’s API and CLI brains and authenticated external MCP. 
{"nodeId":"YOUR_NODE_ID","entryId":"YOUR_AUDIO_ENTRY_ID"}

flowjoe-cli action transcribe_audio --file input.json --wait 3600 --json
Use stable snapshot IDs: entryId names the recording leaf, including inside a stack. No path, URL or provider-setting override is accepted. Missing or sealed recordings are refused. choose_audio returns accessible recording identities: ask the user and retry with one exact entry. local_setup_required means select/install a model in Transcribe and retry. Ctrl+C cancels the run. Success returns saved: true, recordId, method/model and up to 12,000 characters of text. When truncated is true, query transcript history and continue with read_history using its revision/cursor. The same inputs work over MCP. External calls do not open or write to Joe’s chat. See Transcribe audio.

Only in Joe’s chat

Joe works the same on every brain that uses Flow tools (OpenAI, Gemini, and CLI brains such as Claude, Grok and Codex). On a Mac this includes Antigravity; on Windows and Linux, Antigravity can’t use Flow tools yet. His chat inside FlowJoe, whether an OpenAI or Gemini model or an installed tool such as Claude Code answering as Joe, uses most of the actions on this page, plus the FlowJoe actions below that the CLI and other assistants connected from outside cannot call. Those actions never appear in flowjoe-cli actions or in the tools a connected assistant is given, and asking for one by name is refused (unknown_action in the CLI). The last row lists tools built into some brains, not FlowJoe actions.
In Joe’s chatWhat it does
find_picturesRanks the pictures in part of your Flow by what they show, so Joe opens only the best matches. Needs a TypeSafe key; without one, Joe picks pictures by their names.
request_app_workflowShows a card that hands you an existing workflow: restore a saved version, export a node, import a Flow or review changes made on another computer. You confirm in the app’s usual dialog; Joe never runs it himself.
read_terminal_output, read_browser_tabRead terminal lines you shared, or keep reading a browser page you asked about in parts (the page itself still reaches every brain as context). See the note under Read a repository file.
Web search, Code interpreterBuilt into some brains rather than FlowJoe actions. See Bring Your Own Brain.

How to run an example

For each action below, save its JSON input as input.json, replace YOUR_… placeholders with real IDs from flowjoe-cli show --json, and run the command shown. No input file is needed for actions with no inputs. All commands require FlowJoe running with Agent Bridge enabled. Results use the CLI’s JSON envelope; the app’s response is under result, with text and possibly image content blocks. A JSON-looking text block holds the action’s data. --json does not turn an image into a written description. Inspect the actual result before assuming a change succeeded. Private/hidden content remains withheld, even with --autoapprove. Gallery and stack positions start at 0. Only pass itemIndex for a member inside a stack. Files, undo, recent-change history and retained-history and repository cursors are owned by one command’s connection. Content-reader cursors instead bind the target, source revision and identical selectors; using one run list is convenient, but they do not have the history reader’s session restriction. Examples using $result, previous uploads or undo must be steps in one run list, not separate invocations. A two-minute default wait still applies with --autoapprove; the flag removes approval waiting, not processing time. Increase it with --wait when needed.

Read repository state — read_repository

Read the current Flow’s admitted repository status, scoped commit identities/dates, or a saved-versus-committed file comparison. This does not run commands, stage changes, check out files or edit content. Private and Hidden from Joe sources remain withheld. Commit messages and author names are withheld because they can mention hidden paths. Changes and approval: Read only; no approval. Available with external Read or Propose access when the desktop repository service exists, independently of native Joe’s chat setting.
InputRequired?Meaning
repoNodeIdYesRepository node ID from the current Flow snapshot.
viewYesstatus, log or diff.
pathFor diffExact admitted repository-relative file path.
diffScopeNoall, staged or unstaged; staged filtering requires an existing current Changes-list baseline.
limitNo1–12,000 characters; default 12,000.
cursorNoReturned continuation; repeat identical selectors in the same run connection.
{"repoNodeId":"YOUR_REPO_NODE_ID","view":"status"}

flowjoe-cli action read_repository --file input.json --json
Result: Bounded content, source/view, branch/history identity and HEAD provenance, character range and optional nextCursor. Status describes saved gallery bytes against the branch. Deleted paths without an admitted live owner are omitted. Staging is explicitly unavailable unless a matching current Changes list exists. A changed Flow, source, privacy, permission, HEAD or canceled request refuses publication.

Read a repository file — read_repo_file

Choose saved, draft or historical explicitly. Saved reads use native Git bytes. Draft reads require the actual already-open editor model; historical reads require an already-open read-only revision model with a unique admitted current file owner. The action never opens, selects or saves an editor. An unavailable draft is never replaced with saved text. Changes and approval: Read only; no approval. Reading adds no write; the separate editRepoFileText editing verb is reviewed before it changes a file.
InputRequired?Meaning
repoNodeIdYesCurrent repository node ID.
sourceYessaved, draft or historical.
nodeId, entryIdSaved/draftExact current gallery owner and entry identity.
path, oid, revisionTreeOidHistoricalExact repository-relative path and identities of the retained open revision model.
limitNo1–12,000 characters; default 12,000.
cursorNoRepeat the same selectors in the same run connection.
{"repoNodeId":"YOUR_REPO_NODE_ID","nodeId":"YOUR_NODE_ID","entryId":"YOUR_ENTRY_ID","source":"saved"}

flowjoe-cli action read_repo_file --file input.json --json
Result: content, explicit source, path/OID and character range; draft/historical results also identify the captured model revision. Changed file ownership, bytes, privacy, model version or session invalidates continuation. Use one run list for all pages. A fresh command starts a different session. Which text you get depends on source. saved is the file as FlowJoe last saved it (an immutable Git blob), draft is unsaved typing in a repository editor tab that is already open, and historical is an older revision that is already open read-only. These are never substituted for one another. To change a file, propose the separate editRepoFileText editing verb with Propose access. Reading never grants it. Browser-page reading is not available to the CLI or any external client. Joe inside FlowJoe can read a page you explicitly ask about, and on every brain that uses Flow tools (OpenAI, Gemini, and CLI brains such as Claude, Grok and Codex) he can also keep reading it in parts. No external connection, including this CLI, can receive that approval. Model arguments, a native Joe request, or an open tab cannot supply one. A future page grant must bind this connection to an explicit user request, exact page/revision and revocation lifecycle before the action can be listed. Terminal output is likewise not offered externally: Joe’s chat in the desktop app, on every brain that uses Flow tools (OpenAI, Gemini, and CLI brains such as Claude, Grok and Codex), can read terminal lines only after you select them and press Share with Joe on his card (terminal sharing), and that is not available to the CLI or other Agent Bridge assistants.

Read current app facts — get_app_state

Read sampled facts about this running app without changing settings or opening a dialog. These are current observations, not historical evidence or proof that a save is durable. Missing information is reported as unavailable. External bridge permissions describe this connection; Joe’s native chat setting does not grant or remove this connection’s configured Read or Propose access. Changes and approval: Read only; no approval.
InputRequired?Meaning
sectionsYesOne or more unique values: storage, save, conflicts, model, permissions, diagnostics (at most six).
{"sections":["storage","save","permissions"]}

flowjoe-cli action get_app_state --file input.json --json
Result: Bounded, sampled section data, with explicit unavailable fields. It does not reveal credentials or a complete settings dump. A Flow change, revoked permission or canceled request can invalidate an in-progress read. Owner desktop facts do not establish a guest’s permissions or settings.

Find retained history — query_history

Search retained records belonging to the current Flow without opening or switching Joe chats. Accessible owners are checked before search results, snippets and counts are produced. A missing result does not prove something never happened: coverage and retention can be partial. Changes and approval: Read only; no approval.
InputRequired?Meaning
kindYeschat, image, transcript or version.
queryNoSearch text, at most 200 characters.
after, beforeNoInclusive ISO date/time bounds.
nodeIdNoLimit to an accessible node.
limitNoRecords per page, from 1 to 30.
cursorNoPrevious nextCursor; repeat the same filters in the same connection.
{"kind":"chat","query":"launch decision","limit":10}

flowjoe-cli action query_history --file input.json --json
Result: records with stable recordId, revision, source details and snippets, plus explicit coverage and continuation information. Image history provides prompt/model metadata, not image pixels. Version history provides permitted change metadata, not raw old documents or a version restore.

Read a retained history record — read_history

Read bounded historical text identified by query_history. It does not change the current chat, restore a version or grant permission to edit. Historical text is evidence from its cited source. Changes and approval: Read only; no approval.
InputRequired?Meaning
kindYesThe query’s chat, image, transcript or version kind.
recordIdYesExact ID returned by the query.
revisionYesExact revision returned for that record.
limitNoText character budget, from 1 to 12,000.
cursorNoPrevious nextCursor; repeat kind, ID, revision and limit in the same connection.
Save this as steps.json, using a query that returns at least one record: 
[
  {"action":"query_history","input":{"kind":"chat","query":"launch decision","limit":1},"saveAs":"found"},
  {"action":"read_history","input":{"kind":"chat","recordId":{"$result":"found","path":["records",0,"recordId"]},"revision":{"$result":"found","path":["records",0,"revision"]},"limit":2000},"saveAs":"page"}
]

flowjoe-cli run steps.json --json
Result: Bounded text with source/conversation/message citations and character coverage. When page includes nextCursor, a later step in the same list can read the next page by repeating the same inputs and adding "cursor":{"$result":"page","path":["nextCursor"]}. Only add that step when you expect another page; an absent result reference stops the list. Do not paste a cursor into a new CLI command. Changed sources, revisions, Flow or permissions require a fresh query.

Read a document or note file — read_item_content

Read extracted text from a gallery note, text file or supported PDF/Word/ODT/PowerPoint/EPUB. Add itemIndex only for a stack member. For scanned PDFs, startPage selects a 1-based page; follow the result’s continuation guidance. Changes and approval: Read only; no approval.
InputRequired?Meaning
nodeIdYesThe node whose gallery holds the item.
slotIndexYes0-based slot index in that node’s gallery.
itemIndexNoOnly for stack slots: 0-based item index inside the stack.
entryIdNoExpected stable entry ID; a mismatch refuses the read.
itemPathNoNested stack indices, starting at 0; replaces itemIndex.
startChar, endCharNoCharacter range starting at 0; end is exclusive.
startLine, endLineNoLine range starting at 1; end is inclusive.
headingNoExact Markdown heading text, through the next heading. Choose characters, lines or heading, not a combination.
maxCharsNoPage budget, from 512 to 60,000.
cursorNoPrevious nextCursor; repeat all other inputs.
startPageNoOnly for a SCANNED PDF being read as page images: 1-based page to start from. Use it to continue through a long scan (the result tells you the next page). Omit for a normal read.
{
  "nodeId": "YOUR_NODE_ID",
  "slotIndex": 0
}

flowjoe-cli action read_item_content --file input.json --json
Result: Text pages include textContent, source.revision, exact coverage, partial, truncated and, when more remains, nextCursor. Scanned PDFs can instead return page images with page continuation guidance. For example, {"nodeId":"YOUR_NODE_ID","slotIndex":0,"startLine":2001,"endLine":2050} reads those lines rather than just the beginning of the file. A changed or moved target, changed content or revoked access refuses continuation; restart the read. A canceled read is not a successful empty result.

Read a spreadsheet, calendar or rich document — get_island_content

Read one workbench reference’s structured content. Add itemIndex only for a member inside a stack. Use page: true for bounded, addressed pages. An open workbench may be flushed before reading; source.policy identifies flushed or stored evidence. A failed flush is reported as flush_unconfirmed, rather than presenting an unsaved draft as saved content. Changes and approval: Read only; no approval.
InputRequired?Meaning
nodeIdYesThe node whose gallery holds the island.
slotIndexYes0-based slot index in that node’s gallery.
itemIndexNoOnly for stack slots: 0-based item index inside the stack.
{
  "nodeId": "YOUR_NODE_ID",
  "slotIndex": 0
}

flowjoe-cli action get_island_content --file input.json --json
Additional optional inputs:
InputMeaning
pageSet true for addressed paging.
entryId, itemPathExpected entry ID and nested stack path; itemPath replaces itemIndex.
listSheetsList workbook sheet IDs, names and dimensions without cell content.
sheetExact workbook sheet ID or name. Omit to read workbook order.
rangeInclusive A1 range, such as A2001:C2050.
startRow, endRow, startColumn, endColumnAlternative inclusive workbook bounds; rows start at 1, columns use letters.
startBlock, endBlockRich-document block range, starting at 0 with exclusive end; body, then headers and footers.
after, before, timezoneInclusive calendar dates in YYYY-MM-DD and an IANA timezone, such as America/Denver; defaults to calendar timezone or UTC. No recurrence expansion.
limitRecord budget: up to 2,000 workbook cells or 200 calendar/document records.
maxCharsCharacter budget, from 512 to 16,000 for these pages.
cursorPrevious nextCursor; repeat all other inputs.
For example, use one of these as input.json with the command above: 
{"nodeId":"YOUR_NODE_ID","slotIndex":0,"page":true,"sheet":"Sheet1","range":"A2001:C2050"}

{"nodeId":"YOUR_NODE_ID","slotIndex":0,"page":true,"startBlock":100,"endBlock":110}

{"nodeId":"YOUR_NODE_ID","slotIndex":0,"page":true,"after":"2026-10-01","before":"2026-10-31","timezone":"America/Denver"}
Result: content contains JSON text with addressed fragments, including cell/block/event addresses, textOffset and complete. coverage, summary, source.revision, partial, truncated and nextCursor describe the page. A long record can span pages; keep every fragment before moving on. Repeat identical selectors with the cursor in one run list. A changed source or revoked target invalidates continuation rather than silently mixing revisions.

Apply a group of Flow changes — propose_flow_patch

Send an ordered ops array of editing verbs. The simpler apply command wraps this action. validateOnly true checks without applying or queuing. A patch is atomic: a failed operation rolls back that patch. For editRepoFileText, validateOnly also runs the edit’s read-only file checks (the text appears once, the file or open draft is unchanged, the file is editable), and Apply checks them again. Changes and approval: Changes data. Follows app approval rules unless —autoapprove; this includes deletion, memory and task review.
InputRequired?Meaning
opsYesOrdered list of {verb, args} editing operations.
validateOnlyNoCheck without applying or queuing approval; default false.
{
  "ops": [
    {
      "verb": "setNodeSummary",
      "args": {
        "nodeId": "YOUR_NODE_ID",
        "value": "Next steps: review the draft."
      }
    }
  ]
}

flowjoe-cli action propose_flow_patch --file input.json --json
Result: Applied operation results, validation errors or a pending approval. The CLI normally waits for that approval to settle.

Prepare content for the gallery — stage_media

Prepare new content without placing it. Supply exactly one source: text, dataUrl or attachmentId. Raw document text and SVG text are supported; MIME must match kind. Raw media staging is limited to 10 MB. An attachmentId must come from this connection’s upload_attachment. Explicit nodeId chooses the intended destination; omitted uses the selected node. Changes and approval: Prepares content; no Flow edit approval until placement. Requires an available staging capability.
InputRequired?Meaning
kindNoMedia kind; defaults to image (or document when text is given, unless mimeType is image/svg+xml → image). Choices: image, pdf, document, audio, video, spreadsheet, rich-document, calendar.
dataUrlNoSource A: data:MIME;base64,… (at most 10 MB).
attachmentIdNoAn ID returned by upload_attachment in this same connection.
textNoSource C: raw text/markdown/csv/json (kind document) OR raw SVG markup (kind image, mimeType image/svg+xml) — the app encodes + sanitizes it; do NOT base64 it yourself.
mimeTypeNoWith text: the document flavor (default text/markdown) or image/svg+xml for SVG markup.
titleNoOptional entry title.
nodeIdNoIntended destination node; omitted means the currently selected node.
{
  "nodeId": "YOUR_NODE_ID",
  "kind": "document",
  "text": "Meeting notes",
  "mimeType": "text/plain",
  "title": "Meeting notes"
}

flowjoe-cli action stage_media --file input.json --json
Result: A prepared entry and stored-media information. Use the returned entry in addImageSlots or a stack verb in the SAME run list.

Generate an image for placement — generate_image

Use the configured image service and its normal paid credits. The bridge allows at most two generation attempts per connection, including failed attempts; a longer run list must stay within that limit. Optional size and quality can override the app’s generation settings. A style hint applies only when the app’s Generate Images style is None. The external bridge refuses action edit with chat_history_required; to make a variation, use action generate with sourceImageKey or a caller-owned referenceAttachmentId. referenceAttachmentId uses this connection’s uploaded image; sourceImageKey targets an accessible stored image. Select the destination node in FlowJoe before starting generation. The request keeps that destination if you select another node while it runs. A missing, removed, private or hidden destination cannot receive the generated result. Changes and approval: Calls a paid service immediately; —autoapprove is not a billing confirmation. Placement is a separate Flow edit.

Upload an image or text file for this command — upload_attachment

Upload PNG, JPEG, GIF, WebP, plain text, Markdown or CSV. Current limits: 8 MB per file, 12 attachments and 24 MB total per connection. The base64 field has its own encoded-size limit. PDF, Word, audio and video are not accepted by this upload action; use request_file for the app’s normal import flow. Changes and approval: Uploads to temporary connection storage; no Flow edit approval.
InputRequired?Meaning
fileNameYesFile name, 1–180 characters.
mimeTypeYesSupported image or text MIME type.
dataBase64YesFile bytes encoded as base64, without a data: prefix.
{
  "fileName": "hello.txt",
  "mimeType": "text/plain",
  "dataBase64": "SGVsbG8="
}

flowjoe-cli action upload_attachment --file input.json --json
Result: An attachment with id, fileName, mimeType and sizeBytes. Read or stage it later in the SAME run list; it disappears when the command ends.

Read an uploaded attachment or retained attachment memory — read_chat_attachment

Omit mode to read a file uploaded by this MCP connection. Upload IDs belong only to this command. With mode: "memory", read retained attachment evidence from an exact admitted conversation returned by query_history; this never borrows whichever native Joe chat is open. Save an upload step as uploaded before the upload example below. Changes and approval: Read only; no approval.
InputRequired?Meaning
attachmentIdYesUpload: ID from upload_attachment in this connection. Memory: * to list, or exact memory ID returned by the list.
modeNoOmit (or image) for the existing uploaded-file read; use memory for retained text evidence.
recordIdMemoryExact chat recordId returned by query_history.
historyRevisionMemoryThat chat record’s revision from records, not the query’s collection revision.
revisionMemory record/continuationExact listed memory record revision; list continuations use the memory index revision.
startNoReturned nextStart: record offset for *, character offset for an exact memory ID; starts at 0.
limitNoMemory index: 1–30 records; exact memory: 1–12,000 characters.
{
  "attachmentId": {
    "$result": "uploaded",
    "path": [
      "attachment",
      "id"
    ]
  }
}
Use this as a step in the same run list as its prerequisite: 
{
  "action": "read_chat_attachment",
  "input": {
    "attachmentId": {
      "$result": "uploaded",
      "path": [
        "attachment",
        "id"
      ]
    }
  }
}
Result: Uploaded attachment metadata plus image bytes or UTF-8 text content. Use inside a run list. For retained attachment memory, use a query/index/read run list: 
[
  {"action":"query_history","input":{"kind":"chat","query":"YOUR_CONVERSATION_TEXT"},"saveAs":"conversation"},
  {"action":"read_chat_attachment","input":{"mode":"memory","attachmentId":"*","recordId":{"$result":"conversation","path":["records",0,"recordId"]},"historyRevision":{"$result":"conversation","path":["records",0,"revision"]}},"saveAs":"index"},
  {"action":"read_chat_attachment","input":{"mode":"memory","attachmentId":{"$result":"index","path":["records",0,"attachmentId"]},"revision":{"$result":"index","path":["records",0,"revision"]},"recordId":{"$result":"conversation","path":["records",0,"recordId"]},"historyRevision":{"$result":"conversation","path":["records",0,"revision"]},"limit":2000},"saveAs":"memory"}
]
Check that the query returned the intended admitted conversation before using its result. A missing or ambiguous conversation is unavailable. Memory results give textContent, source identity/provenance, revision, range and optional nextStart; use the same record and memory revisions for more. They explicitly say stored_memory_not_original_bytes. A document’s retained memory can remain readable after its original bytes are gone; unavailable or unprovable memories require existing full context or re-sharing. This grants no original-file download or image pixels. Exact retained-memory addresses with both current revisions can be read in a new authenticated command; upload IDs cannot. Changed stored memory, conversation, privacy, Flow/storage authority, permission or cancellation refuses publication. A memory ID cannot select an uploaded file, and an upload ID cannot select retained memory. External memory reads work with native Joe Off. Native CLI brains use only their exact active turn’s conversation; guests and scheduled runs do not inherit this access.

Control music and playlists — control_global_player

Control the header player. The action choices and examples below cover playback, mode and saved playlists. Accessible audio only; this is not a transcript or general media editor. InputRequired?Meaning

Supported staging kinds and file limits

The live staging catalog lists image, PDF, document, audio and video, plus spreadsheet, rich-document and calendar kinds. The external bridge currently cannot stage spreadsheet, rich-document or calendar content, including an uploaded CSV selected as kind spreadsheet. Those importers need a file-attachment handle, while this bridge passes uploaded content to staging as a data URL. Use request_file and the normal app importer for those workbench types. The external upload action also accepts only the image/text MIME types listed above. PDF, Word, audio and video files cannot be uploaded through upload_attachment; use the normal file chooser for them. A raw dataUrl can prepare a supported non-workbench kind when its MIME and size are valid; it does not bypass the workbench restriction. Do not invent an attachment ID or relabel a file’s MIME type. Staging is preparation, not placement; see the working example.
