Change references and stacks

Edit gallery notes, organize references and stacks, crop images, and change canvas items.

Retained chat attachment memory and current gallery content are separate evidence sources. Use the memory read action for saved conversation evidence; it does not recover original gallery bytes. A repository-backed gallery file can be inspected with read_repo_file. The one repository change is editRepoFileText: one exact text change to one existing file, held for your review unless you started the session with --autoapprove. No gallery verb gives terminal access, commits or pushes. Every example below is a separate change. Save its JSON as changes.json, replace all YOUR_… placeholders with IDs from your current Flow, and run: 
flowjoe-cli apply changes.json --preview --json
flowjoe-cli apply changes.json --json
The first command checks without applying. The second follows FlowJoe’s approval rules. Add --autoapprove to the second command to skip all approval cards, including deletions, for that command. Permissions, privacy, frozen content and validation still apply. All verbs on these pages change data; none is a read command. A successful patch reports applied and operation results; a failed operation rolls back that patch. See results and exit codes. A gallery position (slotIndex, index, sourceIndex, fromIndex, toIndex) starts at 0: 0 means first, 1 means second. An itemIndex selects a member inside a stack, also from 0. Only use examples whose targets exist and have the required content type. Examples with two or three positions need at least that many items. Read fresh data after an edit that changes positions. The required inputs below come from the editing catalog measured on 2026-10-20: 62 verb names for 61 distinct changes, because setNodeReadOnly is an older name for setNodeFrozen (discover the running build’s catalog for updates). Where an alternative stable entry ID is listed, supply that instead of its positional field, not both. Read IDs with a gallery snapshot; not every verb supports the same ID alternative. removeEntryContexts uses nested positional references. The live catalog is authoritative for your installed desktop version: 
flowjoe-cli action describe_patch_protocol --json
Prepared-entry examples containing $result belong inside a run action list, after a step saved as prepared; they cannot be pasted unchanged into a standalone apply file. See the complete upload → prepare → place example. Replace that example’s final ops with the operation shown here. Never invent a stored-media key.

Move a gallery item within its node — moveSlotWithinNode

Move one gallery position to another. Read current positions first; both indices start at zero. Required inputs: nodeId, fromIndex, toIndex. Stable IDs: fromEntryId can replace fromIndex; toEntryId can replace toIndex. 
[
  {
    "verb": "moveSlotWithinNode",
    "args": {
      "nodeId": "YOUR_NODE_ID",
      "fromIndex": 0,
      "toIndex": 1
    }
  }
]
Result: The gallery order changes.

Set the complete gallery order — reorderSlots

Give every current gallery index exactly once, in the desired order. This two-item example requires exactly two gallery items. Required inputs: nodeId, order. Stable IDs: orderEntryIds can replace order. 
[
  {
    "verb": "reorderSlots",
    "args": {
      "nodeId": "YOUR_NODE_ID",
      "order": [
        1,
        0
      ]
    }
  }
]
Result: The gallery takes the supplied order.

Result: The node’s gallery is sorted.

Show a slot in another node — addVirtualSlot

Add a virtual slot to a node: it shows an existing slot (its master) and stores no content of its own. masterEntryId is the master slot’s entry ID from anywhere in the Flow; naming a virtual slot points at its master. Optional slotIndex chooses the position (default: the end). Refused into a frozen or Private node, for a master that isn’t in the Flow or sits in a Private node, and for a master in a node hidden from Joe. Required inputs: nodeId, masterEntryId. 
[
  {
    "verb": "addVirtualSlot",
    "args": {
      "nodeId": "OTHER_NODE_ID",
      "masterEntryId": "MASTER_ENTRY_ID"
    }
  }
]
Result: A virtual slot appears in the node, showing the master. Changing the master changes it too.

Turn a virtual slot into its own slot — makeVirtualSlotReal

Make Real Slot: the virtual slot becomes a real copy of its master as it is now, with its own copy of every file, and keeps its place. Refused when the slot isn’t a virtual slot, its master is missing, Private or in a node hidden from Joe, or a file can’t be copied. Required inputs: nodeId, slotIndex. Stable IDs: slotEntryId can replace slotIndex. 
[
  {
    "verb": "makeVirtualSlotReal",
    "args": {
      "nodeId": "YOUR_NODE_ID",
      "slotIndex": 0
    }
  }
]
Result: The slot no longer changes with the master.

Remove a master slot that has virtual slots — removeVirtualMaster

deleteSlots and deleteNode refuse a master that still has virtual slots elsewhere. Use this instead: when you approve it, FlowJoe shows the Remove Master Slot window in the app, and you choose whether one of its virtual slots becomes the new master or they are all removed. Any mode an assistant sends is ignored and the removal is held for your choice. A session started with --autoapprove applies its own mode (promote with promoteEntryId, or remove) without asking and opens nothing in the app; without a mode it is refused. It is held for review like other removals, and refused when one of its virtual slots is in a frozen node or a node hidden from Joe. Required inputs: nodeId, entryId. 
[
  {
    "verb": "removeVirtualMaster",
    "args": {
      "nodeId": "YOUR_NODE_ID",
      "entryId": "MASTER_ENTRY_ID"
    }
  }
]
Result: The master is gone and its virtual slots were handled as you chose.

Change text in one repository file — editRepoFileText

Propose one exact text change to one existing repository file. It must be the only change in its request, so send it on its own. Scheduled tasks and guest sessions cannot use it. Required inputs: nodeId, entryId, source (saved or draft), expectedOid, oldText, newText. Optional: repoNodeId, and draftVersion when source is draft. Read the file first with read_repo_file using the same source, and copy its oid into expectedOid (and, for a draft, its draftVersion). oldText must appear exactly once in the saved file, or in the open unsaved editor draft when source is draft. A draft edit needs that repository editor tab to be open in FlowJoe; a historical revision cannot be edited. Requires Propose access. 
[
  {
    "verb": "editRepoFileText",
    "args": {
      "nodeId": "YOUR_NODE_ID",
      "entryId": "YOUR_FILE_ENTRY_ID",
      "source": "saved",
      "expectedOid": "YOUR_FILE_OID",
      "oldText": "retries = 3",
      "newText": "retries = 5"
    }
  }
]
Result: Held for your review on the approval card, which shows the exact before/after, even when FlowJoe’s Auto-apply setting is on — unless you started this CLI command with --autoapprove, which approves its changes for you. Applying saves the file in FlowJoe only; it does not write your working folder and makes no commit or push. Undo (undo_last_change in the same run list) restores the previous version unless the file was saved again or the open editor tab has newer typing. --preview changes nothing and reports the same refusals the change would get: whether the request is valid, sent alone, and whether oldText appears exactly once in the current saved file or open draft. An ordinary proposal is checked the same way before any card appears, so a stale or non-matching edit is refused right away instead of waiting for review. The card’s own preview and Apply check again; if the file was saved or typed in after the card appeared, Approve stays unavailable or Apply writes nothing, and you reject the card and propose a fresh edit. Refusals: file_edit_must_be_alone, old_text_not_found, old_text_not_unique, draft_changed, changed_meanwhile, not_a_repository_file, editing_blocked (the file is Frozen, Private or read-only) and no_change. For a master removal in an explicit --autoapprove session, send mode: "remove" or mode: "promote" with promoteEntryId. If you omit the choice, virtual_slot_mode_required asks you to send it.
